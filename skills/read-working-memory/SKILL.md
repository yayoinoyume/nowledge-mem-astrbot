# 读取工作记忆

## 简报从哪来
插件在每轮对话前把上下文包（含工作记忆）注入为 `<nowledge_mem_context>`。它是简报，不是完整证据，也不替代针对具体问题的搜索。

## 何时使用
- 新会话开始，或隔一段时间回到某个项目
- 用户问「我在做什么」「最近在忙什么」「我的上下文是什么」
- 需要了解其他工具里产生的近期进展、优先级、未决事项

## 何时不用
- 本会话已经看过简报：不要重复读取，除非用户要求或上下文明显变化
- 用户明确要一个不带历史包袱的新开始
- 任务完全独立、不需要任何历史上下文

## 怎么读
1. 先看注入内容里的焦点领域、优先级、未决标记、近期变化与深链。
2. 只挑与当前任务相关的部分，用自然语言提一句，不要整段复述。
3. 如果任务是续做、复盘、回归、发布或查旧决策，简报之后立刻用 `search-memory` 做一次定向搜索。
4. 需要确认服务、身份或同步是否正常时，用 `nowledge_mem_status`，不要靠猜。

## 没有简报时
- 若本轮没有注入简报，如实说「本轮没有记忆简报」，不要编造用户的近期工作。
- 用 `nowledge_mem_status` 区分三种情况：未配置凭据、服务不可达、鉴权或超时失败。
- 读不到就继续做能做的事；记忆缺席不等于任务无法进行。

## 边界
- 空间与身份由插件配置固定，不要从项目名、目录名或对话内容推断，也不要声称切换了空间。
- 不引用 `<nowledge_mem_context>` 之类包装标签本身。
- 没有真正看到简报内容时，不要声称「已读取工作记忆」。
