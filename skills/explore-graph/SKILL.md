# 展开记忆关系

## 何时使用
- 用户问「这几条记忆怎么连起来的」「有没有相关记忆」「帮我展开邻居」
- 已经搜到若干条结果，需要看它们的上下游、依赖或被引用关系
- 想确认某条结论是不是孤立的

## 种子只从本次结果里取
- 只用这次检索真实返回过的 `memory_id`，按相关度从高到低取前 3-5 个当种子
- 不要凭记忆拼 id，不要把上几次会话的 id 拿来复用，也不要自己编号
- 没有检索结果就先搜；搜不到就如实说没有种子，不要展开

## 怎么调用
`nowledge_mem_graph(memory_id=<某条记忆的 id>, depth=1)`

- `depth` 范围 1-5，默认 1
- 单次邻居最多 50 个，超出部分不会返回
- 返回的是文本形式的邻接信息：邻居节点、边类型、方向
- 返回空表示「无邻居或节点不存在」，这是正常结果，不是报错

## 渐进展开
1. 第一次只给 `depth=1`，把直接邻居讲清楚
2. 用户说「再展开一层」「继续」，才把深度加 1，从当前边缘节点重新展开
3. 最多到 5，到顶就停下并说明已到上限
4. 不要一次拉满：深度越大结果越杂，讲不清等于没讲

## 禁止
- 不要给任何网页链接，也不要提「可视化页面」「打开图看看」
- 不要说「已为你生成关系图」。工具返回的是文本邻接信息，没有图
- 不要因为邻居太少就补编邻居

## 怎么讲结果
按这个顺序说，一次只讲一层：
1. 中心节点是什么：给出 `id`，再一句话说清它讲的结论
2. 邻居按边类型分组说：每组先一句概括，再列关键节点；同类多的只说代表，不要逐个念 id
3. 收尾说清覆盖与未覆盖：展开了几层、哪些方向没展开、哪些节点因为没有邻居而停住

## 边界
- 图只用来补关系，不替代检索；具体结论仍以记忆正文为准
- 空间由插件配置固定；展开结果少不是换空间或改配置的理由
