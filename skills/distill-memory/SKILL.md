# 沉淀记忆

## 原则：主动保存，不等用户开口
对话产生持久价值时就直接保存。不要问「要不要我记下来」，也不要把保存当成会话结束前的仪式。

## 什么时候值得存
- 突破：长时间调试后问题解决、根因确认
- 决策：比较过方案并选定，理由与代价清楚
- 研究：多条路径试过，结论收敛
- 反转：反直觉的原因、被推翻的假设
- 经验：下次该怎么做、如何预防
- 偏好与约束：用户明确表达且会长期生效
- 计划与上下文：下一次会话需要接着做的

## 什么时候不存
- 例行修复，没有可复用的教训
- 还没定稿、很快会变的中间状态
- 文档里就能查到的通用知识
- 纯闲聊、寒暄、一次性问答
- 任何敏感信息：密钥、密码、令牌、身份证号、完整联系方式、私密凭据

## 先查重，再保存
1. 用 `nowledge_mem_search` 搜同主题，确认是否已经有记忆覆盖。
2. 已被完整覆盖：不重复保存。
3. 只有新增信息：保存增量，并在 `content` 里写清它补充或取代哪条记忆的 `id`。
4. 本插件没有更新工具；不要为了「更新」而复制一整条旧内容，保存一条写清补充或取代关系的增量即可。

## 怎么调用
`nowledge_mem_save(content=..., title=..., unit_type=..., importance=..., labels=...)`

- `content`：必填，最多 8000 字符；写清前因后果与「为什么」，不要贴整段对话
- `title`：最多 200 字符，用将来会搜的词
- `unit_type`：`fact`、`preference`、`decision`、`plan`、`procedure`、`learning`、`context`、`event`，默认 `fact`；类型清楚时一定填
- `importance`：0-1，默认 0.6。参考分档：0.8-1.0 重大决策与关键教训；0.5-0.7 有用模式与次要决策；0.3-0.4 背景与细节。这是估值参考，不是硬门槛
- `labels`：最多 20 个，每个最多 64 字符，用主题或项目名，便于以后过滤

## 质量要求
- 一条记忆只讲一个结论，能脱离对话单独读懂
- 写「学到或决定了什么」，不写「我们刚才聊了些什么」
- 标题能搜到，内容有因果，不用表情符号
- 推测与事实分开写；没验证的结论标注为待验证

## 读回执
- 成功返回 `saved: id=... title=... unit_type=... importance=...`
- 内容超长会截断，返回里会带 `note`
- 失败返回 `error:`；没拿到 `saved` 回执就不要说已保存

## 边界
- 空间由插件配置固定；默认写入当前空间，不要自己挑共享空间，也不要在文本里编造空间名
- 只写文本结论，不写凭据、内部地址、完整个人信息
- 保存失败时如实告知，并把内容留在回复里，方便用户稍后重试
