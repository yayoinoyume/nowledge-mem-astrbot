# 搜索记忆

## 先说明，再搜索
搜索前用一句话说明你在找什么，例如「我先查一下之前登录态迁移的结论」。不要默默搜完再宣布。

## 什么时候搜
- 用户引用先前工作、旧修复、旧决策，或说「那个做法」「像之前一样」
- 任务续做某个功能、缺陷、重构、事故或子系统
- 调试现象像以前解决过的问题
- 用户问理由、偏好、流程、惯例
- 需要跨工具上下文或精确的对话历史

## 什么时候不搜
- 全新话题，没有任何历史
- 通用语法或文档里就能查到的答案
- 用户明确要一个不带旧结论的视角
- 不要每句话都搜：一次精准的搜索胜过三次试探

## 检索路由
1. 记忆（决策、流程、偏好、经验）：`nowledge_mem_search(query=..., scope="memories")`
2. 历史对话（原话、当时怎么讨论的）：`scope="threads"`
3. 不确定在哪：`scope="both"`，一次拿到两类结果

参数：
- `query`：3-7 个核心词，具体优于宽泛
- `limit`：1-20，默认 10；先用小值
- `mode`：默认 `normal`；结果弱或问题偏概念时用一次 `deep`，它更慢
- `recorded_date_from` / `recorded_date_to`：按写入 Mem 的时间筛选，格式 `YYYY-MM-DD` 或 ISO 日期；事件时间不可用

## 怎么读结果
- 每条含 `id`、`title`、`content` 摘要、`score`；记忆若来自对话会带 `source_thread`
- `score` 只是排序参考，不设固定阈值：看内容是否真的回答了问题，不要因为分数低就丢掉明显相关的结果，也不要因为分数高就照抄
- 与代码有关的结论，要回到当前代码库核实后再当作现状
- 需要完整内容时用 `nowledge_mem_get(memory_id=...)`；它会返回全文、标题、类型、重要度、标签与 metadata

## 命中对话后
- 用 `nowledge_mem_thread_show(thread_id=..., limit=8, offset=0)` 只看需要的那一小段
- 每个问题最多读一次；已知目标区间可以给一次非零 `offset`
- 不循环翻页拼出整段对话；单条内容最多 500 字，这是固定上限，不要试图放大
- 读不到、超时或不完整时，停下来报告证据缺口，换搜索词，而不是继续翻页

## 空结果与失败
- `no matches`：搜索成功，但没有匹配。如实说「没搜到」，不要把「没搜到」说成「不存在」。
- `error:`：请求失败，例如不可达、鉴权失败或超时。说清是失败，必要时用 `nowledge_mem_status` 诊断。
- 两者不能混为一谈，也不能把失败包装成「没有相关记忆」。

## 引用与空间
- 用记忆或对话支撑结论时，给出 `id` 或 `thread_id`，方便用户回查。
- 空间由插件配置固定；`no matches` 不是换空间或改配置的理由。

## 聚焦图
- 检索成功且有结果、用户明确想看关系时，用 `nowledge_mem_graph(memory_id=..., depth=1)`。
- 用户要更多上下文时最多 `depth=5`；从某个节点展开时一次一跳，去重已访问节点，5 跳内且每跳不超过 50 个邻居就停。
- 空结果不画图。图探索失败时说明原因，保留已检索到的证据，不要声称已经画好或打开。
