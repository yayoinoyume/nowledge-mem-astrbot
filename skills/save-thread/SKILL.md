# 保存会话与交接

## 先讲清事实
插件在每轮对话结束后自动把新增消息增量写入同一个对话线程，不需要手动导入。这个技能做两件事：确认确实落库，以及写一份给下一次开工用的结构化交接。它不执行完整转录导入，也不假装执行。

## 何时使用
- 用户说「保存这次会话」「打个检查点」「交接一下」「留个总结」「记住我们进行到哪」，或「记录一下」「做个交接」
- 一段工作告一段落，需要留下目标、决定、风险与下一步
- 不要在日常对话里自动触发，也不要在用户没要求时反复建议

## 步骤
1. 用 `nowledge_mem_thread_show(thread_id=..., limit=8, offset=0)` 看最近几条消息，确认它们已经在对话线程里。
   - 每个问题只读一次，不要翻页拼整段对话
   - 单条内容最多返回 500 字，这是固定上限
2. 拿不到 `thread_id`、读取失败或超时：如实说「无法确认是否已落库」，不要编造消息条数或线程 id。
3. 用 `nowledge_mem_save` 写一条交接。正文固定五项，缺一项就补上，顺序不要改、不要合并：
   - 目标：这次要完成什么
   - 决定：已经定下的方案与理由
   - 改动面：涉及哪些模块或文件类型，不写敏感路径
   - 风险：还没验证的假设、已知坑
   - 下一步：接着做什么，从哪开始

   写完再按下述传参：`unit_type="context"` 或 `"plan"`，`importance` 0.7-0.9，`labels` 加一个便于检索的交接标签。不要把这行写进五项正文。
4. 返回给用户：线程是否确认、交接记忆的 `id`、覆盖了什么、明确没覆盖什么。

## 与沉淀记忆的分工
- 交接是给下一次开工用的索引，不是把整段对话塞进记忆。
- 本次对话里的具体结论、决策、经验，仍按 `distill-memory` 单独存成原子记忆。

## 硬规矩
- 只由用户显式要求触发。日常对话里绝不自作主张保存会话，也不主动建议「要不要我存一下」。
- 不要把交接说成完整转录导入：它是一份五项结构的摘要，原文落库由插件每轮的增量同步负责。

## 限制
- 一个会话对应一个线程，跨会话不合并
- 只处理文本，图片、语音等不进入记忆
- 自动同步失败时会有待重试批次；`nowledge_mem_status` 的 `pending` 只表示本会话是否有待同步批次（0/1），不是积压条数
- 没有拿到回执时，不要声称「已保存」或「已同步」
